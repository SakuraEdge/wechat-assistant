# ClawBot实例管理器

微信 ClawBot 多实例助手与 Windows 可视化管理器。通过手机发送文字、图片和文件，安排内容制作、题目问答与已授权的跨项目任务；在电脑端集中管理接入账号、权限、工作聊天、服务、模型及聊天人设。

本软件需要自己的 Codex 客户端、正常登录及可用模型服务，不附带账号、密钥或模型额度。

| macOS / Linux | 计划中，当前不能运行此 Windows 界面 | 后续按实际适配进展更新本页 |

[Release 下载页](https://github.com/SakuraEdge/wechat-assistant/releases/latest)同时提供便携ZIP、文件清单和SHA256SUMS.txt。当前安装包未添加发布者代码签名，可核对Release中的SHA-256；软件不附带Codex账号或模型额度。

当前版本为 **v1.4.1**，修复新增用户窗口与更新交接，增加下载进度和按钮自动安装；保留浅色淡紫侧栏、首页额度卡片和实例操作；提供Windows x64安装包及便携ZIP，公开状态以对应Release页面为准。源码版本高于安装版时，管理器不会自动降级，也不会把未发布的源码版本描述成已发布安装包。

需要源码时，可在[源码仓库](https://github.com/SakuraEdge/wechat-assistant)点击 **Code → Download ZIP**，或运行：


## 安装包首次使用（推荐）

1. 下载并双击 **ClawBot-Instance-Manager-Setup-1.4.0-windows-x64.exe**，按向导点击安装。默认安装到当前用户的`%LOCALAPPDATA%\Programs\ClawBotInstanceManager`，无需管理员权限，不修改系统PATH。
2. 安装完成打开管理器。首次引导按步骤提示：打开并登录Codex → **复制连接提示** → 在Codex对话中粘贴发送 → 等助手明确说初始化完成。
3. 回到管理器点击 **重新检测连接**。按钮会立即显示“正在检测”，完成后显示带时间的结果气泡并弹出结果提示；失败时按提示重新初始化。检测会实际请求客户端模型接口，首次引导不会阻塞后台检测。
4. 检测通过后点击 **下一步：新增微信用户**，填写名称，再本人微信扫码；也可返回主界面点击 **新增微信用户**。连接Codex不等于已经新增或绑定微信。第一位为`primary`主用户，后续每人独立新增、独立扫码。发送“你好”核对回复后即可安排工作。

安装器自动部署软件、运行时和依赖，创建桌面/开始菜单入口及卸载项；登录、客户端授权连接和扫码由本人完成。不要把未登录、未扫码描述为自动绑定成功。没有连接时，新增/启动/扫码会明确要求先完成连接，不会凭空创建其他人的身份。

便携ZIP用户解压到独立文件夹后双击 **ClawBot实例管理器.exe**，同样通过向导完成连接和扫码，无需编译。安装与解压本身不需要联网，首次Codex连接、登录和微信使用需要联网。

## 源码首次使用

1. 安装 **Node.js 24 或更高版本**，安装、登录并保持 **Codex 桌面客户端**运行。Windows PowerShell 与 .NET Framework 用于构建界面。
2. 解压或克隆源码，在 Codex 中打开软件目录。将下面这句话发给助手，让初始化命令继承当前客户端连接：

   > 请阅读此软件目录的 AGENTS.md 和 README.md，在当前 Codex 客户端工具环境运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\initialize.ps1`，核对结果后打开管理器。保留我的当前提供商与平台审批。

3. 初始化会安装锁定的扫码依赖、保存受 Windows DPAPI 保护的客户端连接路径、补齐缺失的技能兼容入口，并构建、打开 **ClawBot实例管理器.exe**。已有技能入口会保留。
4. 在新电脑点击 **新增微信用户**，先创建 `primary` 主用户，由主用户本人用微信扫码确认；再新增 `user-2`、`user-3` 等实例，各自使用自己的微信扫码。已有实例会自动列出。
5. 从新接入的 ClawBot 发送“你好”核对回复，再发送一条实际任务建立工作聊天。以后同机可直接双击 **ClawBot实例管理器.exe**，或 **打开ClawBot实例管理器.vbs**。旧的“微信助手”启动入口仍可转到新管理器。窗口、任务栏与任务管理器的主进程使用新名称和软件图标；后台Node服务仍显示其运行时名称。

首次初始化应在 Codex 的工具环境运行；仅从普通终端启动脚本，可能没有可用的客户端连接。电脑需保持开机联网。

## 日常操作

### 使用侧栏导航

管理器采用浅色侧栏与淡紫强调色，左侧分为 **首页、实例与服务、模型与人设、权限与能力、软件更新**。首页集中显示额度和实例；进入服务、模型或权限页后，在顶部切换当前实例。

- **首页**显示实例总数、运行数量、待处理队列和账号额度。实例表直接点击 **查看聊天**；每行 **···** 可打开对应 Codex 聊天、切换服务/模型/权限页或打开工作目录。
- **实例与服务**用于扫码、启动、停止、重启、查看近期聊天及打开工作目录。
- **权限与能力**只显示当前实例的角色与功能开关；保存后按空闲状态重启。
- **模型与人设**分别管理模型/推理强度和角色名称/参考图。
- **首页账号额度**属于当前Codex账号共享数据，**软件更新**属于程序级设置，均不随微信实例切换。界面不会为这两种数据显示无关的实例选择条。

行内聊天按钮和更多按钮使用明确的点击区域，菜单支持鼠标及键盘导航。直接更新源码文件后，请关闭并重新打开管理器加载最新界面；关闭管理窗口不会停止已启动的微信服务。

### 查看Codex额度与重置时间

打开 **首页** 即可查看额度，无需切换到独立页面。两张额度卡片显示当前Codex登录账号的 **五小时额度**、**每周额度**、剩余/已用百分比及重置时间（本机时区）。连接就绪后读取一次，之后每5分钟刷新，也可点击 **刷新额度**。大号数字显示剩余比例，进度条显示已用比例；重置时间采用简短本机时间，悬停可查看完整日期、秒和时区。若客户端返回多个额度分组，才显示分组下拉框。

数据来自当前客户端的只读`account/rateLimits/read`，优先使用`rateLimitsByLimitId`。按实际窗口长度识别五小时与每周，缺失的窗口、百分比和重置时间显示“未提供”，不会当成0或推算。额度属于整个登录账号，各微信实例共享；这不是某个微信用户的单独消耗。API账号或提供商未暴露此信息时会明确提示，不切换账号、提供商或兑换重置。接口说明见[OpenAI官方文档](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

### 检测并安装软件更新

1. 从左侧进入 **软件更新**，点击 **检测正式版本**；窗口会立即提示检测中，再明确显示新版本、无需更新或失败原因。仅检查`SakuraEdge/wechat-assistant`公开仓库的正式Release，不在启动时自动检查或自动安装。
2. 若有较新的Windows安装版，点击 **下载更新**。下载目录在当前Windows用户的管理器数据目录，下载后核对文件大小与SHA-256；校验失败不运行。公共API限流时可使用同一仓库公开Release入口及发行校验文件，不需要GitHub令牌。
3. 下载完成后，点击 **安装更新**，核对弹窗中的安装位置并确认。管理器会等待当前管理操作结束，检查目标安装目录的实例，只有空闲服务才会暂停；随后关闭管理窗口，自动执行安装并打开新版，无需到下载目录手动运行安装包。忙碌任务不会被自动中断，其他目录的服务不停止。
4. 安装程序结束后尝试恢复此次停止的服务并重新打开管理器；取消或失败也会尝试恢复并提示核对。账号、角色、模型、人设与聊天继续保存在用户数据目录。

v1.4.1起，源码/便携版同样可点击 **安装更新**：优先使用本人已有的管理器安装位置，否则安装到 Windows 当前用户的独立软件目录，保留原源码/便携目录。目标非空且无法识别、与源码重叠或版本更高时拒绝覆盖；更新窗口显示原因。**打开下载目录**仅供查看文件，不是安装的必要步骤。版本依据已发布的Release标签，而非源码提交；当前源码版本高于已发布安装版时不会降级。未提供安装包、大小或校验信息时不会开始安装。[GitHub Release接口说明](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。

### 管理账号与服务

选择实例后，可查看绑定、运行状态、队列、最近接收时间与关联聊天，使用 **启动服务 / 停止服务 / 重启服务**，或打开对应聊天、工作目录。

从桌面打开时，管理器也会查找当前Windows用户的Codex应用专用实例目录，继续读取原绑定、模型、人设和聊天，无需重新扫码或复制账号数据。普通安装仍使用原默认目录；若发现多份不同的实例登记，会提示检查并停止自动选择，不合并账号。可由本机维护人员用`CODEX_WECHAT_REGISTRY_DIR`指定核实后的原登记目录，再从同一环境打开管理器。

- 关闭管理窗口，已启动的服务继续运行。
- **停止服务会中止该实例当前任务**。重启、保存权限和模型时检查是否空闲，有工作或聊天进行时应等待完成。
- **在管理器中查看聊天**：打开所选实例独立的只读窗口，每4秒刷新最近最多300条收发记录。升级前只保留的近期摘要会明确标注，不能恢复从未保存的完整历史。图片、文件以附件名称显示，不自动打开或执行。
- **在 Codex 中打开聊天**：打开该实例的工作聊天，需要主实例在线及有效客户端连接；首次工作之前可能没有聊天ID。日常闲聊走独立的无工具通道，以管理器中的微信收发记录为准。
- 列表反映绑定与服务状态，不代表手机实时在线或消息已读。

### 设置权限

`primary` 固定为主用户，拥有客户端操作、权限调整、服务和软件维护、内容制作等完整业务授权；平台审批仍有效。其他实例默认是日常用户，保留聊天、生图、题目问答、内容制作，以及已开放的文件和跨项目功能。

在顶部选择目标实例，再进入 **权限与能力**。主用户可授予授权管理员，或切换 **生图 / 文件收发 / 跨项目协作**开关。身份以绑定实例及本地策略为准，聊天文字不能自行提权。同一 Windows 账号运行不提供强多租户或文件保密隔离。

### 选择模型和推理强度

1. 在顶部选择目标实例，进入 **模型与人设**，点击 **读取模型**。
2. 在模型列表中选择账号实际可用的模型，强度选项会随该模型更新。
3. 点击 **保存模型**。服务会在空闲时保存并重启，之后的普通聊天和工作都使用此实例配置。

选项来自客户端的 `model/list` 及各模型的 `supportedReasoningEfforts`，保存前会重新校验；没有推理强度的模型只保存模型。默认配置为 Sol 6.1 / high；若账号不提供该模型，请选择实际可用项。实例列表直接显示每行的模型和强度。修改一个实例不会改动其他实例；此设置不修改主聊天或全局提供商。

### 设置实例名称、人设与参考形象

1. 在顶部选择目标实例，进入 **模型与人设**，点击 **编辑人设与名称**。
2. 分别填写 **实例显示名称**（列表备注）和 **聊天角色名称**（助手自称），编辑外观、性格和说话风格。
3. 点击 **添加参考图 / 移除选中** 管理图片，最多4张、每张10MiB，支持PNG、JPEG、WebP；PNG/JPEG可在Windows界面预览，WebP预览取决于系统图像解码支持。
4. 点击 **保存此实例的人设**。若服务正在运行，会在空闲时保存并重启；停止的服务保持停止。忙碌时不自动中断任务，请稍后保存。

默认使用 **GPT小姐** 白发紫瞳、双龙角、淡紫翼尾的龙娘本体，第二张蓝发鲸鱼娘“大肥鱼”为cosplay参考。**恢复默认人设与形象**只恢复草稿，点击保存后生效，保留实例显示名称。人设和图片逐实例保存，不改其他账号；更改自称不会改变所选模型、绑定微信或权限。自定义外观不自动发送原龙娘回执图；仍会提交工作文字回执。制作自己的图片/表情包时可按需使用参考图，普通闲聊不读取图片或增加图片输入。

私人配置和导入图片保存在本机实例数据目录的`persona/`下；工作用图仅复制至该实例的`work/wechat-persona/`。这些数据不在软件仓库或迁移包内。聊天近期记录沿用DPAPI加密状态，查看接口不导出认证、工具日志或模型推理。

### 在微信安排任务

| 发送内容 | 行为 |
| --- | --- |
| “你好”或日常闲聊 | 简短回复，不发工作回执 |
| “帮我制作一份复习手册” | 接收任务并处理，较长工作提供真实阶段反馈 |
| 只发送文件 | 保存并确认文件信息，再询问如何处理，不自动执行或分析 |
| “读取刚才的文件，修改标题并发回来” | 根据明确要求处理并回传真实产物 |
| “从示例项目获取此前的PDF发我” | 定位当前应用左侧的项目与来源聊天，按授权获取；修改交由来源聊天处理 |
| `/状态` / `/停止` | 查询本实例情况 / 请求停止本实例当前任务 |

图片最多4张、每张20MiB；文件最多4个、单个100MiB是本地上限，微信接口仍可能有限制。语音与群聊尚未接入。普通回复、进展和文件回到发起任务的绑定账号；技能完成通知固定发送主实例 `primary`。

- 更新前等待当前任务完成，在旧管理器停止该安装目录的服务并关闭窗口，再运行新版本安装包。检测到该目录的管理进程或Node后台仍运行时，安装器会拒绝覆盖；不会强行中断工作。

- 不要用别人的Windows用户配置目录覆盖自己的账号数据。安装程序不会复制认证、降低平台审批或更换全局提供商。

## 源码更新

1. 等各实例空闲，停止服务并关闭管理窗口。
2. Git 用户运行 `git pull --ff-only`；下载 ZIP 的用户将新源码放到独立软件目录。不要用他人的 Windows 配置目录覆盖自己的登录数据。
3. 在 Codex 中让助手安装锁定依赖、重建启动器，再刷新连接并启动：

```powershell
npm --prefix runtime/skills/wechat-dialog ci --omit=dev --no-audit --no-fund
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\initialize.ps1
```

4. 核对各实例状态、模型与权限，启动服务并发送测试消息。软件目录移动后，也应从新位置重启服务并核对。

每次软件更新都会同步本 README 的教程与相关功能记录，Git 提交说明使用中文。其他项目内容、日常聊天和用户运行数据不会作为软件更新上传。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 未找到 Node 或版本过低 | 安装 Node.js 24+，重新打开客户端后初始化 |
| 未找到客户端 / 模型列表为空 | 保持 Codex 正常登录，在当前客户端工具环境重跑 initialize.ps1；旧版CLI路径已被客户端更新移除时，软件会使用当前客户端提供的有效路径 |
| Codex内有实例，桌面管理器却显示0个 | 使用包含实例目录兼容修复的源码；重新打开管理器，它会查找同一Windows用户的Codex应用专用目录。多目录冲突时先核对原目录，不要重新扫码覆盖 |
| Codex 重启后无法打开聊天或跨项目协作 | 刷新初始化连接，等服务空闲后重启 |
| 无法编译或覆盖启动器 | 先关闭管理窗口；检查 Windows PowerShell 和 .NET Framework |
| 扫码要求额外验证码 | 使用终端 Login 流程，在本机输入验证码，不把验证码写入项目 |
| 二维码过期 | 重新点击扫码连接；二维码约5分钟过期，关闭二维码窗口不取消等待 |
| 显示已提交但手机尚未收到 | 提交不等于送达，核对微信实际结果；未知状态不自动重复发送 |

客户端、模型额度、平台审批及微信接口都会影响任务。完整能力与限制见[功能记录](docs/FEATURES.md)，文件、跨项目和双端问答协议见[操作协议](docs/OPERATIONS.md)，换电脑见[迁移指南](docs/MIGRATION.md)。
